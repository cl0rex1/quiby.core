# Quiby: серверная сборка 6.1.29

Minecraft **1.21.1**, NeoForge **21.1.250**, Java **21**. 37 основных JAR,
включая Create, Aeronautics, Sable, Off Balance, Explosion Overhaul, дополнения
Create, Create Nuclear 2.0.0, Quiby и Simple Voice Chat. Вложенные зависимости сохранены внутри JAR.
18 клиентских/ненужных на сервере JAR исключены; список и SHA-256 находятся
в `server-pack.json`. Графика, шейдеры, ресурспаки, пользовательские аккаунты,
миры, скриншоты и секреты в архив не входят.

## Сначала обновить компоненты входа

В этой сборке включена проверка аккаунта **до появления игрока в мире**.
Нужны обновлённый API с `/api/game/join-ticket` и
`/api/game/verify-join-ticket`, лаунчер с `prepareGameAdmission` и клиентский
**quiby.mod 1.1.22** и Create Radars **5.0-EA-3.1.4-1.21.1**. Новая клиентская сборка **6.1.29** и лаунчер 1.1.3 содержат нужный протокол входа.
Старый лаунчер и старый клиентский Quiby будут отклонены. Серверный мод сам не обновляет клиент.
До обновления Minecraft-сервера доставьте клиентам сборку 6.1.29.

Лаунчер получает после Discord-входа билет только для Minecraft и создаёт
временную пару Ed25519. Перед входом сервер проверяет билет, ник, UUID,
актуальное разрешение аккаунта в API и подпись своего случайного запроса.
Discord/API токен не передаётся в игру; закрытый ключ не передаётся серверу.
Без билета/ключа, при неверной подписи или недоступном API вход закрыт.
Билет действует 12 часов: после истечения нужно перезапустить игру из лаунчера.
Одиночная игра не требует серверной проверки.

Это аутентификация разрешённого аккаунта, а не доказательство неизменности
программы на чужом компьютере. Владелец аккаунта, который намеренно переносит
временные ключи в изменённый клиент, находится за пределами этой гарантии.

Для наших Discord-аккаунтов `online-mode=false`. Ванильный whitelist отключён,
поскольку разрешение проверяется по `is_whitelisted` в Quiby API. Не удаляйте
серверный Quiby и не отключайте `quiby-access-server.toml/enabled` на публичном
сервере с этим режимом: без проверки ник можно подделать.

## Ubuntu / CasaOS: Docker

Распаковать **готовый ZIP**, а не только `deploy/minecraft` из Git:

```bash
mkdir -p ~/quiby-minecraft
unzip quiby-server-6.1.29.zip -d ~/quiby-minecraft
cd ~/quiby-minecraft
```

Прочитайте [Minecraft EULA](https://aka.ms/MinecraftEULA). Если принимаете условия:

```bash
EULA=true MAX_MEMORY=8G docker compose up -d --build
docker compose logs -f --tail=100 minecraft
```

После установки образа можно импортировать прилагаемый `docker-compose.yml`
в CasaOS. Укажите `EULA=true`, `MIN_MEMORY=2G`, `MAX_MEMORY=8G` в настройках
контейнера. На машине с 8 ГБ общей памяти выделяйте Java меньше, например 5–6 ГБ.
При запуске без этих переменных по умолчанию максимум Java 8 ГБ, минимум 2 ГБ;
принятие EULA автоматически не подразумевается.

Мир, конфиги, моды и библиотеки хранятся в отдельном Docker volume
`minecraft-data`; обычное `docker compose down` их сохраняет. **Не используйте
`docker compose down -v`**, если хотите сохранить мир. Контейнер работает
от UID/GID 10001. Для bind mount вместо volume каталог должен быть доступен
этому пользователю.

При первом запуске устанавливается фиксированный NeoForge через официальный
installer; для скачивания Minecraft и библиотек нужен интернет. Installer
включён в ZIP, его SHA-256 проверяется перед запуском. Библиотеки устанавливаются
в целевом Linux-контейнере, клиентские Windows-библиотеки не переносятся.
Java 21 поставляется Docker-образом `eclipse-temurin:21-jre-jammy`.

Проверка и остановка:

```bash
docker compose ps
docker inspect -f '{{.RestartCount}}' quiby-minecraft
docker compose logs --tail=150 minecraft
docker compose stop minecraft
```

Запускайте консоль, когда нужны игровые команды:

```bash
docker attach quiby-minecraft
```

Отсоединение от консоли: `Ctrl+P`, затем `Ctrl+Q`. Команда `stop` выключает сервер.
Первый администратор может получить права командой `op ВашНик` из консоли;
проверка входа Quiby защищает в том числе этот ник.

## Ubuntu без Docker

Нужны `python3` и Java 21. Скрипт не установит другую Java молча:

```bash
java -version
python3 --version
chmod +x start.sh
# После принятия EULA:
EULA=true MAX_MEMORY=8G ./start.sh
```

Для существующего сервера остановите его, сохраните резервную копию всего мира
и укажите `SERVER_DIR=/полный/путь/к/серверу ./start.sh`. Настройки и мир не
заменяются целиком. Старые управляемые JAR удаляются с резервной копией только
если их имена есть в `quiby-installed-mods.json` от предыдущей установки.
При первом переносе существующего сервера вручную уберите старый Quiby JAR и
клиентские моды, чтобы не получить две версии одного мода.

## Автоматические настройки

В сборке доступны `quiby-community-server.toml`
и соблюдение окна перезапуска в `start.sh`/`restart_wait.py`. Расписание по Астане:
06:59 с повторным запуском не раньше 07:01 и ежедневно 20:00 с паузой 30 секунд.
Обратный отсчёт в игре начинается за минуту. Нужен обновлённый Quiby на сервере
и клиентах; повторный запуск процесса обеспечивает Docker/supervisor.
Мод не перезагружает ОС. При отдельном запуске через свой скрипт вызывайте
`restart_wait.py` из рабочего каталога данных до старта Java.

Discord-мост включается только после согласованного обновления API и бота:
одинаковый `GAME_BRIDGE_API_KEY` от 32 символов в API и Minecraft,
`GAME_BRIDGE_API_URL` — доступный серверу адрес API (по умолчанию
`https://api.quiby.me`). Docker Compose передаёт их в контейнер; без ключа мост
выключен. У бота отдельно нужны `MINECRAFT_CHAT_ENABLED=true`, Message Content
Intent и права вебхуков. Подробности: `quiby.mod/docs/community-update.md`.
Церемония и меню описаны в docs/releases/6.1.29.md основного репозитория.

На каждом запуске `prepare.py` проверяет хэши JAR и применяет
`config-policy.json`. Прочие настройки в существующих файлах сохраняются;
изменённые файлы копируются в `quiby-backups/`. На пустой установке копируются
42 исходных серверных/common конфигов и конфиг входа. Для серверных TOML
обновляются `config`, `defaultconfigs` и, если мир уже существует,
`<level-name>/serverconfig`. Учитывается `level-name` из `server.properties`.

Фиксируются:

- Off Balance: `balanceEnabled=false`, `hurtProxyEnabled=true`,
  `hurtProxyMobsTarget=true`, `recoveryGateEnabled=false`,
  `dismountRequireGrounded=true`.
- Quiby: `minDamage=9.0` — 4,5 сердца за один удар после защиты;
  реакции на урон/взрыв включены, cooldown 20 тиков. Усиление импульса взрыва
  и возврат к offline-телу реализованы в моде.
- Sable: `minDismountTicks=20` — 1 секунда при 20 TPS;
  `debugLogging=false`, чтобы не засорять консоль.
- Explosion Overhaul: `enableExplosionClustering=false`.
  Обычные и breeze wind charge используют ванильный взрыв.
  Сохранены исходные списки защищённых блоков и стекла. При запуске выделенного
  сервера существующий индекс блоков загружается автоматически; если его нет,
  он строится без первоначального запроса администратору. Отключение индексации
  в common-конфиге по-прежнему учитывается.
- Проверка входа Quiby включена, API `https://api.quiby.me`.

Пользовательские `.env`, `ops.json`, существующий `server.properties`,
бан-листы, whitelist и миры не переписываются шаблонами. До ручного изменения
управляемых параметров измените политику: иначе следующий запуск вернёт их.

## Подключение и проверка

Порты: **TCP 25565** для игры, **UDP 24454** для Simple Voice Chat. Адрес
голосового сервера можно задать в `config/voicechat/voicechat-server.properties`.
Без белого IP эти порты ещё нужно доставить через выбранную сеть/туннель;
архив сам не открывает интернет-доступ. Обычный HTTP Cloudflare Tunnel API
не переносит игровой TCP и голосовой UDP.

Локальная проверка: отдельный Java 21 dedicated server, существующий тестовый
мир, загрузка до `Done`, прослушивание игрового порта, запуск Voice Chat,
чистая остановка. Исправлен найденный при проверке dedicated-server баг
возврата к offline-рэгдоллу: поиск метода Sable больше не загружает ClientLevel.
Есть upstream warnings о необязательных интеграциях и ошибки отдельных данных
Create-аддонов; они не остановили загрузку. Linux/Docker на этой Windows-машине
не запускался. Вход реального игрока надо подтвердить после совместного
обновления API, лаунчера и клиентского Quiby.

## Повторная сборка в репозитории

Python 3.11+; установленная сборка из `.quiby-launcher`; собранный
`quiby.mod/build/libs/quiby-1.21.1-1.1.22.jar` в соседнем репозитории:

```powershell
python scripts/test-server-pack.py
python scripts/build-server-pack.py
```

Можно передать `--source`, `--quiby-jar`, `--output`. Неизвестные JAR,
отсутствующие серверные зависимости и несовпадающие хэши останавливают сборку.
ZIP имеет фиксированные timestamps, сортировку и права исполнения `start.sh`;
рядом создаётся файл `.sha256`. Сборка не публикует GitHub Releases и не меняет
работающие контейнеры API/CasaOS.
