# GitHub Releases: сборка и обновления

Публичные файлы лежат отдельно от приватного исходного репозитория:

- [Сборка Season 6](https://github.com/cl0rex1/quiby-modpacks/releases) — манифест и 226 объектов (174 игровых файла и 52 иконки). Текущая версия: `v6.1.0`.
- [Windows-лаунчер](https://github.com/cl0rex1/quiby-launcher-releases/releases) — NSIS-установщик, blockmap и `beta.yml`. Текущая версия: `v1.0.1-beta.2`.

Лаунчер загружает `https://github.com/cl0rex1/quiby-modpacks/releases/latest/download/manifest.json`, проверяет SHA-256 каждого изменённого файла и сохраняет файлы с политикой `keep_local`. Если GitHub временно недоступен, использует API. Для локальной проверки неопубликованной сборки можно запустить процесс лаунчера с `QUIBY_PACK_SOURCE=local`.

При запуске установленный Windows-лаунчер проверяет GitHub Releases. В **Настройки → Файлы и Java** можно повторить проверку, скачать обновление и перезапустить приложение для установки. Сейчас канал `beta`. Новую версию нужно выпустить с увеличенным номером `apps/launcher/package.json`.

Вход в лаунчер выполняется через Discord OAuth. Лаунчер по умолчанию использует `https://api.quiby.me`; для локальной разработки адрес API задаётся через `VITE_QUIBY_API_URL` при сборке. В Discord Developer Portal должен быть зарегистрирован redirect `http://localhost:45678/callback`.

## Выпуск следующей версии сборки

1. Обновите исходный профиль Modrinth и импортируйте его: `npm run pack:import`.
2. Увеличьте `version` в `modpacks/quiby-s6/manifest.json` (скрипт импорта также может обновить версию).
3. Запустите `node scripts/publish-github-release.mjs pack --check`, затем `npm run pack:release`.

Скрипт сверяет SHA-256 с локальными файлами, создаёт черновик, загружает все объекты и манифест последним, затем публикует релиз. Неизменённые файлы разных версий получают один и тот же хеш в имени, но хранятся в каждом релизе отдельно. Старые опубликованные релизы остаются доступными для отката.

## Выпуск следующей версии лаунчера

1. Увеличьте `version` в `apps/launcher/package.json` и синхронизируйте `package-lock.json` командой `npm install --package-lock-only`.
2. Соберите и опубликуйте: `npm run release:github --workspace apps/launcher`.

Публикуются имена файлов, указанные в `beta.yml`, включая blockmap. Скрипт не изменяет уже опубликованную версию: для нового кода нужен новый номер. Для работы скрипта нужен вход через Git Credential Manager или переменная `GITHUB_TOKEN` с правом Contents: write в соответствующих публичных репозиториях.

Текущий выпуск предварительный: установщик не подписан. После развёртывания HTTPS API проверьте вход Discord на чистой машине и выпустите новую версию установщика.
