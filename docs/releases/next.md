# Выпуск 1.1.0 / сборка 6.1.24

Лаунчер 1.1.0 и сборка 6.1.24 опубликованы 22.10.2026. Выпуск согласует API 1.1.0, бот 0.0.7 и Quiby 1.1.17. Подробные заметки: `1.1.0.md`.

## Ресурспаки: вложения до 20 МиБ

- Устаревший предел 8 МиБ заменён на 20 МиБ (20 971 520 байт) в подготовке ZIP, отправке заявки лаунчером, обоих маршрутах приёма файла API и доставке вложения ботом.
- В лаунчере и API используется общий лимит. При превышении API отвечает 413 с понятным сообщением о размере.
- Решение администрации, проверка SHA-1, приватные временные ссылки и ограничения очереди (64 МиБ, 10 минут) сохранены. Импорт локального ZIP до 100 МиБ не равнозначен допуску или отправке заявки.
- Проверены файлы больше 8 МиБ, ровно 20 МиБ, 20 МиБ + 1 байт и пустой файл. Проверки API, доставки ботом и настоящего IPC в собранном Electron выполняются с изолированными файлами и имитацией сети, без сообщений в рабочем Discord.

Для выпуска нужно согласованно обновить quiby.core (лаунчер и API) и quiby.bot; одного обновления лаунчера недостаточно. Выпуск разрешён пользователем 22.10.2026.

## Панель управления: контент и игроки

- Вайтлист разделён на «Все», «Моды», «Ресурспаки» и «Другое» (появляется только при наличии записей). Фильтрация и счётчики выполняются в API до разбиения на страницы. Поиск и страницы сохраняются отдельно по категориям.
- Ручной допуск принимает JAR и ZIP. ZIP можно выбрать в браузере: имя и SHA-1 заполняются без отправки архива на сервер. Решения по ресурспакам отдельно подписываются в журнале.
- «Доступ к лаунчеру» перенесён внутрь «Игроков» рядом с «Аккаунтами». Старый адрес раздела перенаправляется на новый.
- В списке игроков доступны фильтры личного доступа и исключений, наигранное время и копирование Discord ID. В заявках можно скопировать SHA-1.
- Общую блокировку можно обойти только для выбранных администрацией игроков с разрешённым личным доступом. Личный запрет важнее исключения и сбрасывает его. Повторное открытие личного доступа не восстанавливает исключение автоматически.
- Лаунчер проверяет персональный доступ по подписанной сессии. Вход через Discord во время общей блокировки доступен при наличии исключений, но сессия выдаётся только после проверки настоящего Discord ID. Подставной ID, токен привязки и недействительная сессия не дают исключения.
- Добавляется колонка users.launcher_access_exempt с безопасным значением по умолчанию 0. Обновление API и лаунчера требуется вместе; старые клиенты не знают персональных исключений.

Источник лимита: [Discord Developer Reference](https://github.com/discord/discord-api-docs/blob/main/developers/reference.mdx#uploading-files).

## Скины ragdoll: стандартное туловище при правильных конечностях

- В `quiby.mod` подготовлено восстановление отсутствующего профиля туловища по явно связанным частям того же ragdoll. Основание — найденные в сохранении мира туловища без `SkinUuid`, с именем `Player`, при сохранённых профилях конечностей.
- При неизвестном владельце или конфликте UUID восстановление не выполняется. Меняются только поля скина; инвентарь, здоровье и физика сохраняются. Исправленный профиль сохраняется и синхронизируется клиентам.
- Кэш клиентских скинов объединён по UUID для обычного игрока, туловища и конечностей. Служебные и устаревшие имена больше не создают отдельные загрузки скина. Запасной поиск по нику для именованных манекенов сохранён.
- Проверки восстановления профиля и общего кэша прошли. Отдельный тест на сервере NeoForge с Sable и Off Balance дважды воспроизвёл потерю профиля туловища и подтвердил восстановление без изменения остальных NBT-полей. Описание: `quiby.mod/docs/ragdoll-skins.md`. Визуальную проверку обращения в Minecraft нужно выполнить перед выпуском.
- Quiby 1.1.17 включён в опубликованную сборку 6.1.24; требуется согласованное серверное обновление.

## Игровое меню, onbar, чат и перезапуски

- В `quiby.mod` подготовлены меню с прежним дирижаблем и шейдерами, быстрый вход на Quiby, автоматическое добавление `play.quiby.me:25565` в список серверов и логотип сезона в табе. На паузе — размытый игровой мир, без дирижабля.
- Сброс захвата исчезнувшего ragdoll освобождает ПКМ. Позиция возврата к офлайн-телу поднята на дополнительный блок с проверкой свободного места. Порог скорости удара Sable снижен до 8 м/с; прочие множители урона сохранены.
- `onbar` выше actionbar показывает 60-секундный отсчёт перезапуска, объявления и ник/время офлайна тела под прицелом. Время выхода сохраняется в данных мира; старые тела без времени не получают выдуманную дату.
- Ежедневные перезапуски по Астане: остановка 06:59 с ожиданием запуска до 07:01 и короткий перезапуск в 20:00. В комплект сервера добавлен `restart_wait.py`, который соблюдает сохранённое модом окно перед запуском JVM. Автоматический повтор запуска требует Docker/supervisor; перезапуск ОС остаётся внешним.
- Вход/выход: жирные `[+] nickname` / `[−] nickname` с запрошенными цветами. Чат по умолчанию локальный в радиусе 100 блоков и одном измерении; `!`, `/g`, `/l` и кнопка канала управляют глобальными/локальными сообщениями. Добавлены подсказки `@nickname` и звуковые упоминания.
- API получил раздельно защищённые очереди `/api/game/bridge` и `/api/bot/chat`, идентификаторы против повторной вставки и аватары из скинов. Локалка отправляется ботом только в админский канал `1562535685435555950`; глобалка, вход/выход и обратные сообщения — в общий `1226861270578364447`. Отправка не блокирует игровой поток. Вебхук получает имя/аватар персонажа для каждого сообщения.
- Фото из общего Discord-чата открываются внутри игры: вписать, приблизить, перетащить, сбросить, вернуться в чат. Только разрешённые Discord CDN, с ограничением размера, без переходов по редиректам. При ошибке подтверждения доставленное сообщение не отправляется повторно в пределах жизни процесса.
- Добавлены 408 русских ключей для обновлённых/новых модов; проверка покрытия прошла для 38 пространств имён текущей сборки.
- Проверены Java-сборка, настоящий клиент и отдельный dedicated server, API/бот с имитацией сети, очереди, упоминания, разграничение локального/общего каналов и ожидание запуска. Рабочий Discord не вызывался. Для фото в клиентском сценарии использовалась локальная картинка.

Для будущего включения моста нужны одинаковый новый `GAME_BRIDGE_API_KEY` (от 32 символов) в API и Minecraft-сервере, `MINECRAFT_CHAT_ENABLED=true` у бота, Message Content Intent и права на вебхуки в двух каналах. Секретов нет в клиенте. Полная инструкция и известные ограничения: `quiby.mod/docs/community-update.md`. Версии не повышены, JAR в манифесте не заменён, публикации и развёртывания нет.

Диагностика пинга: текущий HAProxy на VPS пересылает игровой TCP через WireGuard домой. Измерено около 40 мс до VPS и в среднем 68 мс от VPS до домашнего узла; Minecraft-порт дома в момент проверки не принимал соединения. Изменять сеть в рамках подготовки не стали: соединение игроков друг с другом не сокращает маршрут до выделенного мира.

## Отдельная проба прямого туннеля — 22.10.2026

По отдельному запросу пользователя подготовлена и начата проверка frp XTCP с
резервным STCP: координатор на московском VPS, provider на домашнем сервере,
visitor в Windows. Публичный адрес Minecraft, HAProxy, WireGuard, API, бот,
лаунчер и манифест не менялись. Использован свободный TCP 443, уже разрешённый
существующим firewall; новое правило не добавлялось.

Настоящие процессы установили прямое QUIC-соединение внутри домашней сети.
Диагностический обмен: медиана около 2 мс напрямую и 113 мс через Москву.
Это не результат для внешнего игрока. Во время этого замера Minecraft в Crafty
был остановлен, поэтому использован отдельный ограниченный echo-сервис.

В `deploy/direct` добавлены генератор приватных тестовых пакетов, проверка
Minecraft ping/pong и тесты контрольных сумм/протокола/настроек. Ключи случайные,
TLS проверяется своим сертификатом, локальный порт visitor доступен только
через loopback. Конфиги, ключи и бинарники создаются в игнорируемом каталоге.
Публичный клиент с общим тестовым ключом не выпускается. Описание пробы и
ограничения: `deploy/direct/README.md`.

После запуска Minecraft реальный ping/pong: 1,15 мс через LAN direct, 95,35 мс
через обычный адрес и 89,42 мс через принудительный STCP с домашнего ПК.
Внешняя проба с VPS: публичный NAT-туннель не установился; резерв STCP работает
(60,67 мс с VPS). Без запрета частных маршрутов frp выбрал существующий WireGuard,
что не подтверждает обход VPS для игроков. Внешнее снижение пинга пока не
подтверждено. Диагностические visitor остановлены; координатор ограничен
двухчасовым сроком и отдельным таймером остановки. Подготовлен приватный пакет
для проверки из сети доверенного игрока; публичный релиз не создавался.

## /ping

Живой ping/pong раз в секунду в onbar, среднее пяти замеров и MSPT.
Три секунды без ответа скрывают старое значение; выход отключает монитор.
Пройдены модульная проверка и настоящий клиентский сценарий с ответом сервера.
