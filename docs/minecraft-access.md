# Управление запуском Minecraft

Админка: **Игроки → Запуск Minecraft** (`/admin/#players/minecraft`).
Настройка не зависит от доступа к лаунчеру. По умолчанию новый запрет выключен.
Можно закрыть запуск всем и указать сообщение до 500 символов. В «Аккаунтах»
есть отдельные исключения Minecraft и личный запрет запуска игры. Личный
запрет имеет приоритет и снимает исключение; полный запрет аккаунта снимает
оба исключения — лаунчера и Minecraft.

API проверяет запрет при выдаче игрового билета и повторно при входе на сервер,
поэтому ранее выданный билет не обходит новое ограничение. Уже подключённые
игроки продолжают играть; синхронизация наигранного времени остаётся доступной.
Лаунчер, новости и настройки доступны, если их собственная политика это разрешает.

Операции админки требуют существующую сессию администратора и защиту от CSRF,
изменения записываются в журнал. Исключение определяется по подтверждённой
Discord-сессии, а не переданному клиентом ID. Прямой транспорт не отменяет
проверку билета на сервере.

## Установка 24.10.2026

API и админка установлены в образе
`quiby-core-api:minecraft-access-20261024t093732z`. Миграция добавляет отдельную
таблицу политики и два поля игрока. База сохранена перед обновлением:
`/app/data/backups/pre-minecraft-access-20261024T093732Z.sqlite` внутри API.
Отпечатки политики лаунчера, списка доступа и активной сборки до/после совпали.
Контейнер Minecraft не перезапускался. Новая политика остаётся открытой.
Релизы сборки 6.1.40 и лаунчера 1.1.6 не заменялись.

В текущем опубликованном лаунчере запрет действует через отказ в выдаче
игрового билета до старта JVM; сообщение об отказе в нём общее.
В исходниках следующего обновления лаунчера добавлены ранняя проверка до
скачивания файлов, сообщение администратора у кнопки запуска, обновление
статуса каждые 30 секунд/при фокусе и ручная повторная проверка. Этот клиент
собран локально, новый установщик не опубликован.

Проверки: сборки API/лаунчера и TypeScript; 15 UI-сценариев; проверки игрового
допуска, общего и личного запрета, исключений, сохранения времени, direct,
поддерживаемой версии и существующего доступа к лаунчеру. Образ проверен на
Linux без сети до переключения рабочего API. Внешние запросы подтвердили
новый endpoint, новую вкладку админки и отказ 401 без сессии администратора.

`deploy/casaos/install-minecraft-access.py` устанавливает подготовленный архив
в существующий API, делает резервную копию, сохраняет политику и откатывает
образ при ошибке проверки. Повторно запускать для уже установленной версии не нужно.
