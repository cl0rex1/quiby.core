# Веб-панель quiby

Адрес: https://api.quiby.me/admin/ — тот же API-контейнер, порт 3001 и существующий Cloudflare Tunnel. Дополнительный контейнер и DNS-запись не требуются.

Вход: значение ADMIN_API_KEY из deploy/casaos/.env. Не публикуйте ключ и не добавляйте его в URL. Он используется только при входе; браузер получает HttpOnly/SameSite=Strict cookie на 2 часа. В production cookie передаётся только через HTTPS. Смена ADMIN_API_KEY отзывает ранее выданные сессии панели. Секреты остаются в существующем .env.

Панель обновляет списки в фоне раз в минуту без очистки уже показанных записей; неизменившиеся строки сохраняют DOM и фокус. Во время ввода и работы в диалогах обновление приостанавливается. Сетевые ошибки не разлогинивают администратора: показана кнопка повтора, запрос ограничен 15 секундами. Раздел хранится в адресе, поиск и фильтры сохраняются отдельно для каждой вкладки в рамках открытой страницы. Клавиша `/` переводит фокус в поиск.

В разделе «Доступ к лаунчеру» показаны фактический серверный статус, время изменения и предпросмотр сообщения. До загрузки настроек сохранение недоступно. Черновик не теряется при переходе в другие разделы, а обновление страницы предупреждает о несохранённых изменениях. Доступ меняется только кнопкой «Сохранить доступ». На телефонах навигация прокручивается горизонтально.

Статика `/admin/` отдаётся с `Cache-Control: no-store`, а HTML ссылается на версионированные CSS/JS. Это предотвращает смешивание старых скриптов в CDN с новой разметкой после развёртывания.

В выпуске 1.1.0: «Вайтлист контента» фильтруется по категориям «Моды», «Ресурспаки» и «Другое»; последние показываются только при наличии соответствующих записей. Ручной допуск поддерживает ZIP и JAR. «Доступ к лаунчеру» находится внутри раздела «Игроки». В карточке аккаунта отдельно настраиваются личный доступ и исключение из общей блокировки. Личный запрет отменяет исключение; повторное разрешение личного доступа не возвращает его. Для исключений необходимы обновлённые API и лаунчер; они включены в выпуск 1.1.0.

Возможности:
- Список заявок на моды, поиск, фильтр статусов и страницы. Одобрение, отклонение, отзыв решения с причиной.
- Ручной допуск/запрет конкретного SHA-1 файла.
- Аккаунты игроков: Discord ID, ник, UUID, даты входа, разрешение и закрытие доступа.
- Рассмотрение заявок на смену ника через существующий сервис. При одобрении изменяется UUID; данные мира по старому UUID автоматически не переносятся.
- Журнал изменений, выполненных через панель, и сводка активной сборки.

Закрытие доступа применяется при следующей серверной проверке сессии или запуске; уже подключённый клиент автоматически не отключается. Удаления аккаунтов и мира в панели нет. Журнал панели не включает действия старых API-эндпоинтов или бота. Ручной допуск конкретного SHA-1 разрешает Gamma/Fullbright; без одобрения такие моды блокируются.

Обновление на Ubuntu:
```bash
cd ~/quiby.core
git pull --ff-only
cd deploy/casaos
docker compose up -d --build api
docker compose ps
docker compose logs --tail=50 api
curl -I https://api.quiby.me/admin/
```

Сделайте резервную копию каталога deploy/casaos/data перед обновлением. Миграция добавляет таблицу admin_audit, не меняя существующие аккаунты и решения. Лаунчер, Minecraft-сервер и бот ради панели обновлять не нужно.

## Добавление JAR

Кнопка «Загрузить JAR» читает название, версию и SHA-1 в браузере (до 512 МБ). Сам файл не отправляется на сервер и не сохраняется там. После проверки заполненных полей выберите решение и укажите причину. Для нестандартных архивов остаётся ручной ввод SHA-1.

Лаунчер отображает постоянную плашку при закрытом доступе и отключает запуск игры. Статус обновляется каждые 30 секунд и при возвращении в окно; сетевые ошибки не меняют ранее полученный статус. Эта функция требует новой сборки лаунчера.

## Автоматические записи и большие JAR

Лаунчер отправляет сведения о неразрешённых пользовательских модах при добавлении, обновлении их статуса и проверке перед запуском: Discord-аккаунт определяется сервером из сессии, сохраняются имя файла, SHA-1, размер и причина. Сам JAR не передаётся. Записи появляются в «Моды и вайтлист» с пометкой автоматического обнаружения и ожидают решения; это сигнал проверки, а не доказательство нарушения. Повторные проверки не дублируют запись и не сбрасывают решение. Такие записи не отправляются боту как обычные заявки.

Ручное одобрение по SHA-1 разрешает конкретный JAR, включая файлы больше 100 МБ (до 512 МБ). Для больших файлов полная автоматическая распаковка пропускается: администратор должен проверить файл самостоятельно. Обычный каталог Modrinth такого исключения не даёт. Повреждённые/неполностью проверенные архивы до 100 МБ по-прежнему не допускаются. Изменение байтов требует нового одобрения. Пределы Discord-вложений не изменены.
