# Проверка клиентского исправления музыки — 23.10.2026

Опубликована сборка 6.1.37, quiby.mod 1.1.30. GitHub latest и реальная функция лаунчера `getLatestModpackManifest` возвращают 6.1.37. Публично скачанный JAR проверен по SHA-256; OGG внутри совпадает с проверенным ресурсом `056a4bbed70a1dd3488c3ed1fe9e2957dae96a9595401b697b9d2921a3142779`. Все 178 путей, хэшей и размеров манифеста проверены.

Старый ресурс воспроизводимо отклоняется штатным Minecraft JOrbis (`Invalid Ogg identification packet`): первый логический поток содержал видеообложку Theora. Новый содержит только Vorbis. Декодировано 14,88 секунды; RMS 0,11436, peak 0,80414. В настоящем клиенте после серверной команды: четыре queued OpenAL buffers, положительные source/listener gains, AL_PLAYING и изменяющаяся позиция. MUSIC=0, RECORDS=0. Это заменяет прежний недостаточный критерий `SoundManager.isActive`.

Реальный аутентифицированный клиент 1.1.30 успешно вошёл на изолированный сервер 1.1.29. Серверная логика и протокол допуска в исправлении не менялись, рабочий Minecraft не останавливался. Public status после выпуска: онлайн. Серверный ZIP 6.1.37 опубликован для следующих установок, но сейчас не устанавливался.

Лаунчер/API остаются 1.1.5. Резервный манифест API пока 6.1.36: CasaOS показывает страницу входа, действующей административной сессии нет. Основной источник лаунчера — GitHub Releases, получение исправленной версии 6.1.37 проверено через его настоящую функцию. При следующем доступе к CasaOS следует синхронизировать резервный API-манифест с опубликованным, без перезапуска Minecraft. Никакие ограничения доступа и данные пользователей не менялись.
