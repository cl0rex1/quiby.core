# Сборка 6.1.40 / quiby.mod 1.1.33 — 24.10.2026

Опубликована сборка 6.1.40 с quiby.mod 1.1.33. Лаунчер и API остаются 1.1.6.

Включены первая катсцена прибытия около костра открытия, безопасные раздельные
места для одновременного входа, предоставленный звук, дым CBC и возврат в первое
лицо. Добавлено попадание невзрывных снарядов/осколков CBC по рэгдоллам;
выход из рэгдолла сохраняет накопленное падение.

Геометрия метеорита подготавливается один раз на сцену; вдали уменьшается число
деталей, не рисуется персонаж и не создаются невидимые частицы. Учитывается
настройка частиц Minecraft. Убраны повторное построение колец посадки и проверки
занятых столбцов по нескольким высотам. Прогресс прибытия хранится по UUID в мире.

На этом ПК, при 4 чанках и 60 FPS, медиана CPU-времени этапа отрисовки сцены:
119800 → 108100 нс, p95: 223200 → 189900 нс; 297/298 измеренных кадров.
Это локальный замер этапа катсцены, а не обещание общего прироста FPS.

Проверены Gradle build/check, настоящий клиент со звуком OpenAL и очисткой
состояния, 25 одновременных прибытий, родные попадания пулемёта/автопушки/дроби/
зенитных и шрапнельных осколков, а также выход/повторный вход в рэгдолл при
падении. На отдельном сервере Chunky 1.4.23 завершил круг радиусом 256 блоков
при подготовленной границе мира 64 блока. Все тестовые JAR и обходы входа
остаются в изолированных каталогах и не входят в выпуск.

В серверный архив включён Chunky только для сервера. Его задания сохраняются и
продолжаются после перезапуска. Установщик по умолчанию сохраняет мир;
`--reset-world --pregenerate-radius 5000` используется только по отдельному
запросу владельца. До замены файлов обязательны объявление перезапуска за 15
секунд, остановка прежнего JVM и свежее подтверждение сохранения всех измерений.
Старый мир сохраняется и в проверенном архиве, и в отдельном каталоге резервных
копий. Аккаунты API, исключения доступа и текущая блокировка не изменяются.

Для заказанного нового мира: подготовка костра у нового спавна, закрытая
церемония, круговая прогрузка радиусом 5000 блоков и окончательное сохранение.
Контроль прогрузки возобновляется и после ежедневного перезапуска домашнего
сервера. Подтверждение готовности: `quiby-season-ready-640.json` в каталоге игры.
Открытие сезона остаётся ручным: `/quiby opening start`.

Рабочий Minecraft обновлён после объявления перезапуска за 15 секунд и
подтверждённого сохранения всех измерений. Проверены новые JAR, новый случайный
сид, архив и отдельная сохранённая папка прежнего мира:

- `/crafty/backups/quiby-pre-640-20261024T005045Z.tar.gz`
- `/crafty/backups/quiby-world-before-640-20261024T005045Z`

API уже отдаёт 6.1.40, mod 1.1.33 и 178 клиентских файлов. Текущая блокировка
лаунчера сохранена; её публичное состояние совпадает с исходным. Данные
аккаунтов, облачное время и исключения доступа не изменялись.

При длительной прогрузке выявлены два нативных SIGSEGV в рабочих потоках C2ME:
сначала Ubuntu OpenJDK 21.0.10, затем Temurin 21.0.13. На этом сервере C2ME
перемещён в отдельную резервную папку, а локальный `server-pack.json` содержит
37 активных модов и запись `serverOverrides` с причиной, путём и контрольной
суммой отключённого JAR. Клиентские файлы и опубликованные архивы не
перезаписывались. Проверки остальных серверных JAR сохранены.

Для рабочего сервера отдельно установлена официальная Temurin 21.0.13+9;
`start.sh` выбирает её из `runtime/jdk-21.0.13+9`. Системная Java сохранена.
SHA-256 архива поставщика:
`d7f5d5cf865a2902b70ff549b97586a7d3f234e016f041ab447ea740c7d66d1c`.

Сохранённая подготовка открытия проверена по NBT: спавн и костёр — `(0,68,0)`,
граница — 64 блока, полдень, циклы времени и погоды отключены, сезон ещё закрыт.
Перед продолжением Chunky принудительно сохранены настройки и контрольная
точка задания. Контроль прогрузки также восстанавливает задание, если JVM
аварийно завершился до первого сохранения состояния Chunky; уже готовые чанки
пропускаются.

Прогрузка круга радиусом 5000 блоков продолжается. Финальная проверка и
подтверждение сохранения будут дописаны после её завершения.
