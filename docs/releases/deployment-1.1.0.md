## Эксплуатация и откат

Приватные файлы установки находятся в `$HOME/quiby-releases/1.1.0` (режим 700).
В `api.override.json` и `bot.override.json` есть рабочие переменные окружения;
не публикуйте их. Обычный перезапуск контейнеров сохраняет эти настройки.
Для пересоздания используйте исходный Compose вместе с соответствующим override.

Перед установкой сделаны онлайн-копия SQLite, снимок конфигурации Crafty и
архив Minecraft (мир, моды, конфиги и служебные файлы). Библиотеки, кэш и старые
архивы в повторный архив не включались. Снимки:

- API: `data/backups/pre-110-20261021T213458Z.sqlite` в существующей папке API.
- Minecraft: `/crafty/backups/quiby-pre-624-20261021T213458Z.tar.gz` внутри Crafty.
- Crafty DB: `/crafty/backups/quiby-crafty-pre-624-20261021T213458Z.sqlite`.
- Старые образы: `quiby-core-api:before-110-20261021t213458z` и
  `quiby-bot:before-007-20261021t213458z`.

Резервные копии содержат приватные данные. Откат мира/базы выполняйте только
после остановки соответствующей службы, предварительно сохранив новые данные.

В Crafty включён `crash_detection`, а `ignored_exits` пуст: выход мода с кодом 0
тоже вызывает повторный запуск. Ручная кнопка остановки Crafty удаляет watcher
и не запускает сервер снова. Перед JVM выполняется `restart_wait.py`; утренний
маркер переживает перезапуск контейнера/хоста. Закрытый `.quiby-bridge.env`
подгружается обёрткой команды Crafty; в публичных архивах его нет.

В прежних журналах найден SIGSEGV `libjvm.so / Method::purge` на Ubuntu Java
21.0.10. Java в этом выпуске не менялась; причина старого падения не установлена.
Контрольные запуск и перезапуск прошли, длительная нагрузочная проверка не проводилась.
Пробный direct остаётся отдельным ограниченным тестом и не включён в лаунчер.
